EDITING THE DATABASE
====================

    scripts/edit-database [--database FILE]

The database is the one given to scripts/setup unless --database (-d)
is given.

The music files are not modified
--------------------------------

The editor changes the database only.  It never writes to the music
files: not for tag edits, renames, ratings, duplicate marks or
removing files from the library.

After the database is created (02-creating-a-database.txt) it is the
master copy of the tags:

  * The player and the phone app read tags from the database, not from
    the files.
  * A change made to a file's tags by another program is not seen.
  * Ratings, play counts, duplicate marks and playlists exist only in
    the database.

Window
------

Left side, four tabs:

  Files       folders and files, with columns for the main tags,
              rating, plays, last played, format, duplicate mark,
              pathname and missing standard tags.  Click a heading to
              sort; right-click it to choose columns.
  Tags        every tag name and its values.
  Duplicates  songs marked as duplicates of one another.
  Playlists   see 04 to 06.

Right side: the tag editor for the selected files.

Select files, or folders (a folder stands for the files in it).  The
tag editor shows one row per tag:

    Tag      Value                Files
    GENRE    Jazz; Hard Bop       3 of 5

  * If the selected files that have the tag agree, the value is shown.
  * If they differ, "<multiple values>" is shown.  Typing a value
    replaces it in all selected files.
  * "Files" shows how many of the selected files have the tag, when
    not all do.

Above the tag list, "<pathname>" shows where the selected file is.  It
is not a tag: it is not stored in the file or in the database, and it
cannot be edited.  It shows the full pathname in two parts: the music
root, in a dimmed colour, then the relative path, which is what the
database stores for the file.  Several selected files show their
common folder and "<N files>".  Hover over it to see the root.

The Pathname column of the Files tab shows the same, per file, with
the root dimmed.  Sorting by it sorts by the full pathname.  When the
column is too narrow the start of the root is cut off first, never the
end of the path.  The root is recorded once in the database; to change
it, see 02.

Finding files
-------------

  * The search box matches files whose path or tag values have a word
    starting with every word typed.  The player's search language
    applies (10): "=whole", "a phrase" and "genre:classical" to limit a
    word to the title, artist, album, genre, composer or path.
  * "Only files missing standard tags" lists files that lack Title,
    Artist, Album, Genre, Tracknumber or Date (the checked ones).  A
    tag with only blank values counts as missing.

Editing
-------

  1. Select files.
  2. Double-click a value, type, press Enter.  The row turns bold.
  3. Click Save (Ctrl+S).

Revert discards unsaved edits.  Selecting other files with unsaved
edits asks to Save, Discard or Cancel.  The title bar shows * while
edits are unsaved.

  * An emptied value removes the tag.
  * Remove Tag (or Delete) marks the selected rows for removal (shown
    struck through); repeating it restores them.
  * Add Tag adds a row: type the name (made upper case; no "=" or line
    break), then the value.
  * A tag with 1 to 300 distinct values in the library is edited with a
    combo box of those values; a new value can be typed.
  * TRACKNUMBER is stored as an integer ("3/12" becomes 3).

Multiple values
---------------

A tag can have several values in one file.  They are stored separately,
in order, and shown joined by "; ":

    GENRE    Rock; Blues

To set several values, type them separated by ";":

    Rock; Blues

On Enter the text is split at ";", the parts are trimmed, empty parts
are dropped, and repeated values are kept once.

";" splits only in a tag that takes several values.  A tag does if
any of these is true:

  1. It is ARTIST, ALBUMARTIST, GENRE, SUBGENRE, STYLE or COMPOSER.
  2. A selected file already has several values for it.
  3. It has a pick list (see above).

In any other tag the text is one value.  A value box that splits shows
the tip "Several values: separate them with ';'".

Add Value and Remove Value change one value in every selected file and
keep the other values:

  1. Select files.
  2. Select an existing tag row.
  3. Click Add Value... or Remove Value... (or use the row's
     right-click menu).

  * Add Value appends the value to each file that lacks it.  Adding
    "Blues" to GENRE: "Rock" becomes "Rock; Blues"; "Blues" is
    unchanged.  In a list tag, "A; B" adds two values.
  * Remove Value lists the values in the selection with file counts and
    removes the chosen one from each file that has it.

Both ask for confirmation, naming how many files change, and are stored
at once without Save.  Unsaved edits are first saved or discarded.  The
player's tag editor has the same two buttons and works the same way on
the selected tracks.

Tags tab
--------

Lists each tag with its values, the number of files with each value, and
the number of spellings that could be unified.  Selecting a value
selects its files in the Files tab.

To change a value in all files, double-click it, type the new text,
and press Enter.  After confirmation it is stored at once.  In a list
tag, "A; B" splits the value into two.

To delete a whole tag (every value, from every file that has it), select
its row, right-click > Delete ... from all files, or press Delete.
After confirmation it is stored at once.  The music files are not
touched.  Filters do not limit this: the tag goes from all files.

Filters:

  * Only variant spellings: values that differ only in spelling or
    case, such as "A and his orchestra" and "A & His Orchestra".
  * Only lists to split: values of list tags that contain "," or "/",
    which are usually several values.  Rename each using "; " between
    the parts.

Saving
------

Save stores the edits for the selected files.  Add Value, Remove Value,
Tags-tab renames and ratings are stored immediately.  There is no
undo except Revert before saving.  Back up the database file before
large changes.  Scan for New Files and Remove from library make a
backup and a journal and report their paths.

Ratings
-------

Select files and use the Rating menu or right-click > Rate.  See
07-song-rating.txt.  Rating more than 25 files asks first.

Duplicates
----------

The Duplicates tab lists groups of songs with the same artist and
title.  One file in each group is the primary; the others are marked as
its duplicates.

  Make primary          make the selected duplicate the primary
  Undo duplicate mark   clear the mark of the selected duplicates; on a
                        primary, clear the whole group

Marks exist only in the database.

BPM and loudness of selected files
----------------------------------

Select files, or folders (a folder stands for the files in it), then
choose from the Analyse menu or right-click > Analyse:

  Detect BPM         Estimates the tempo from the sound, as
                     desktop/bpm_batch.py does for the whole library.
                     Files that already have a BPM are not analysed.
                     A result rated high or medium reliability becomes
                     the BPM tag; a low one is listed and the file
                     stays at 0.
  Measure loudness   Measures every selected file (EBU R128, with
                     ffmpeg) and stores the loudness and the true peak
                     that volume leveling uses.  A value already there
                     is replaced.

A progress window with a Cancel button shows the work; more than 500
files asks first.  The results are stored in the database only; the
media files are not touched.  Each action backs up the database
(.bak-before-bpm-detect or .bak-before-loudness) and appends to a
journal (bpm-detect-journal.jsonl or loudness-journal.jsonl) beside the
database.  Unsaved tag edits are saved or discarded first.  The player
has the same two entries in the right-click menu of the song list.

Scrubbing tags
--------------

To delete whole tags from the selected files only, select the files or
folders and choose Tags > Scrub Tags from Selected Files, or right-click
> Scrub tags.  The dialog lists every tag name the selected files have,
with the number of files that have it.  Tick the ones to delete (All but
standard ticks everything except TITLE, ARTIST, ALBUM, GENRE,
TRACKNUMBER and DATE), then confirm.  All values of a ticked tag are
deleted from the database; the music files are not touched, and the
change is saved at once, like the other bulk changes.

Adding and removing files
-------------------------

  * File > Scan for New Files... adds files that are new in the music
    folder, and handles removed ones.
  * Right-click files > Remove N files from library... deletes them,
    with their tags, plays, ratings and playlist entries, from the
    database.  The files on disk stay, and a later scan lists them as
    new if they are still in the music folder, unless "Yes, and ignore
    them in scans" is clicked instead of Yes (see below).
  * The New tab of the scan dialog has two columns.  The left one lists
    the new files found, with no tick boxes.  Select files (Shift or
    Ctrl-click, Ctrl+A; the filter box above the list narrows it to files
    whose path, title, artist or album contain the words typed) and click
    one of the buttons between the columns to move them to the right:

      Add to database     the files are added with their tags
      Ignore in future    scans no longer list the files
      Delete from disk    the files, and the folders that become empty,
                          are deleted (a confirmation lists them first;
                          this cannot be undone)

    "Put back" moves selected files on the right back to the left.
    Files left on the left are not touched and are listed again by the
    next scan.  Nothing happens until Apply is clicked; Cancel discards
    every choice.  The Missing and Changed tabs keep their tick boxes
    (Shift-click a tick box to tick or untick all of them).
  * The Ignored tab lists the ignored files.  Select files and click
    "Stop ignoring selected files" to have scans list them again (a
    file that is on disk comes back to the left column at once).
    File > Ignored Scan Files... shows the same list outside a scan.
    The list is stored in the database (the meta table).  Ignoring
    never affects files that are already in the database.
  * The same dialog has a checkbox, "Also delete the files from the disk,
    and the folders that become empty".  Checked, the files are deleted
    from the music folder (they cannot be recovered; the database can,
    from the backup and the journal), and so is each folder that is then
    empty, going up to but not including the music folder.  A folder
    that still holds other files, such as cover art, stays.  Files that
    cannot be deleted are listed afterwards.  Nothing outside the music
    folder is ever deleted.  Copies on the phone are not deleted (11).

File > Sync with Phone... merges plays and ratings from the phone.
