GETTING THE DATABASE AND THE MUSIC ONTO THE PHONE
=================================================

The phone app plays from a library folder holding two things:

  * tags.db, a copy of the desktop database;
  * the music files.

The folder is <SD card>/MusicLibrary, or /storage/emulated/0/MusicLibrary
if there is no card (see 09).  Syncing puts both there, and brings the
plays and ratings made on the phone back to the desktop.  The same
operation is used for the first copy and for later updates.

Snippets saved in the player's Samples tab (10) are files of the database
like any other, in the folder Track Samples of the music folder, so the
next sync copies them too.

Ringtones
---------

The playlist "Track Samples" of the Samples tab (04) is not sent to the
phone, and one that the phone has is removed: only the files go.

Every file in the folder Track Samples is also copied, by the same sync, to
the Ringtones folder of the phone's internal storage (/Ringtones), so that
it can be chosen in the phone's sound settings (Settings > Sounds and
vibration > Ringtone).  The copy in the library stays: the app plays the
snippets from it and from the playlist "Track Samples".
  * The file keeps its name and its type (a ringtone made from a FLAC song
    is a FLAC file; not every phone accepts every type as a ringtone).
  * Only files that are not there, or differ in size, are copied.
  * Nothing is deleted from the Ringtones folder, ever: removing a ringtone
    is done on the phone.
  * After each file the app tells Android's media scanner, so the ringtone
    list shows it at once.
  * The phone needs the app of this version (older apps answer that they
    take no ringtones; the sync then says so and goes on) and the
    permission "All files access" that the app already asks for (09).
  * The sync from the command line (android/tools/sync_phone.py) does this
    too, over the network; the cable method (--adb) does not.

Install the app first (09).

Wi-Fi sync from the player or editor
------------------------------------

1. On the phone: open the app, tap the "..." button, choose "Sync with
   the desktop..." and tap Start.  The app shows a pairing code, the
   phone's address and the port (8765).
2. On the desktop: File > Sync with Phone...
3. Enter the pairing code.  The last five codes are remembered, one per
   phone, and can be picked from the list.  Leave "Phone address" empty
   unless the phone is not found.
4. Leave "Also copy new music to the phone" checked to copy music, or
   uncheck it to sync the database only.
5. Click Sync.  The log lists the steps, and the line under it says
   what is happening now.  While music is copied, a bar shows the files
   done of the total, and the line gives the file being copied, the GB
   done of the total, the speed and the time left.

The phone and the computer must be on the same Wi-Fi.  The phone is
found by a UDP broadcast (port 8766); if that does not work, enter its
address.  With USB tethering the phone is reached through the gateway.
The sync server runs in the app: do not close it during the sync.  While
it runs, its dialog on the phone is modal: a tap outside it or the Back
key does not close it; use its Close button, which also stops the sync
server.

Stopping a sync
---------------

Click Close on the desktop (or press Escape) while a transfer runs: the
transfer stops and the dialog closes at once.  The requests in use are
broken off, so a phone that went to sleep, and does not answer, cannot
keep the dialog open.  Files already copied stay on the phone, and the
next sync copies the rest.

If the phone goes away during the copy (its sync dialog closed, the app
stopped, the Wi-Fi lost), the desktop gives up after six files in a row
fail, with "The phone stopped answering; giving up", and the dialog stays
open with the log.  Nothing is hung; Close works.

Command line
------------

    scripts/sync-phone [--code CODE] [--host ADDRESS] [--no-music]
                       [--force] [--desktop-db FILE]

Same procedure, over Wi-Fi.  With no --code it uses the remembered codes
(stored in phone-link.json in the database's folder) or asks for one.
--no-music syncs the database only.  The database is the one given to
scripts/setup unless --desktop-db is given.

The script stops if the player or the editor is running (they keep the
database in memory and would overwrite the result).  --force skips this
check.

USB cable with adb
------------------

    scripts/sync-phone --adb [--dest PATH] [--no-music]

Needs USB debugging on the phone (09) and the adb installed in the BOD.
--dest is the library folder on the phone, for example
/storage/XXXX-XXXX/MusicLibrary; the default is the SD card of one
particular phone, so give your own.  The card's identifier is the name shown by
"adb shell ls /storage".

The app is stopped, tags.db is copied from <dest>, merged and copied
back, and then the music is copied with adb.

What a sync does
----------------

1. Copies the phone's tags.db to the desktop.  A new phone has none and
   gets the desktop's.
2. Merges what the phone changed:
     * play count, last played time and rating of each song: the newer
       write wins (every write is stamped with the time it was made);
     * dynamic-playlist entries played on the phone: they leave the
       lists and are replaced, as if played on the desktop (05).
3. Backs up the desktop database to <database>.bak-before-phone-sync
   (before the first merge of a run) and sends the merged database to
   the phone.  If the phone played something since step 1, steps 1 to 3
   are repeated, up to three times.
4. Copies music that the phone does not have, unless disabled.

Everything else in the database (tags, playlists, rules, containers) is
edited on the desktop only.  The phone's copy of those is replaced by the
desktop's at each sync; nothing changed on the phone is kept.

Music copying
-------------

  * All songs in the database are copied, with the cover images (jpg,
    jpeg, png) under the music folder.  Duplicates are copied too,
    except where a name collision is described below.
  * A song already on the phone with the same size is skipped, so an
    interrupted copy continues where it stopped.
  * The first sync copies the whole library.  Check the free space on
    the card.  A "folder: ..." line names each folder (relative to the
    music root) as the copy reaches it.  A progress line every 100 files
    shows files, gigabytes, speed and the estimated time left; a failed
    file is tried three times.
  * The card's file system cannot hold some characters.  File and folder
    names are cleaned the same way on the phone and the desktop:
      - each of  * ? : " < > |  \ and control characters becomes _
      - trailing dots and spaces become _
      - names that differ only in capital letters are one name; the
        file that is not the primary is skipped and listed
  * Songs removed from the library are not deleted from the phone.

Safety of the sync
------------------

The sync is meant for a network you trust (your own Wi-Fi, or USB
tethering).  The phone's server runs only while sync is started in the app,
and every request must carry the pairing code.
  * The code is sent as it is, and the data is not encrypted: anybody who
    can watch the network traffic while you sync can read the code and the
    files.  Do not sync on a shared or public Wi-Fi.  "New code" in the
    app changes the code.
  * Five wrong codes lock the server until sync is stopped and started
    again.
  * A connection that stops sending its request is closed after 20 seconds;
    one address can have 8 connections open, and all together 64.
  * A file that would leave less than 50 MB free on the phone is refused.
  * The desktop keeps the codes of the phones it knows in its settings file
    and, for sync_phone.py, in phone-link.json next to the database; both
    are readable by your user only.

Reviewing what the phone changed
--------------------------------

Songs often cannot be rated while driving.  When a sync from the player
or editor takes plays or ratings from the phone, a "Changes from the
phone" window opens after the sync dialog closes.  It lists those songs
with their rating, what the desktop had before ("Was"), the play count,
the last played time and how long the song was heard in its latest play
("Listened", minutes:seconds; blank when the phone did not record it).  The
phone writes the time when the song ends or is left, and only for a song that
counted as played (20 seconds); the desktop database gets the column when it
is opened.  The rating cell shows a "0" and five
stars.  Click a star to give that many stars, or the "0" to give zero stars
(a song not yet rated shows them all faint, and zero stars shows the "0" in
full; a double-click makes a song not rated; a click anywhere else in the
cell changes nothing).  Or select songs and press 0 to 5 (Delete: not
rated); right-click > Rate does the same.  "Only songs that are not rated" shows
the ones still to rate.  The ratings given are only shown in the list
until Apply stores them: Apply then takes every rated song off the list
and leaves the window open for the songs that are still not rated, so
with "Only songs that are not rated" checked the list shrinks to what is
left to do.  Finish stores the ratings given since the last Apply and
closes the window.  Cancel (or Escape, after a question) closes the
window without storing the ratings given since the last Apply.  Being
newer than the phone's, the stored ratings go to the phone at the next
sync.

File > Review Phone Changes reopens the list of the last sync until the
program is closed.

After syncing
-------------

The app reloads the database when it returns to the foreground.  If the
song list is empty, open "..." > Library, check that the database and music
folder paths are those of the library folder, and tap Load library.

Errors
------

  "Close the desktop player and editor first"
      Close them, or use --force.
  "The phone's sync server was not found"
      Start the sync on the phone ("..." > Sync with the desktop... >
      Start), check that both are on the same Wi-Fi, or give the
      address.
  "... refused the pairing code"
      The code changed ("New code") or belongs to another phone.
  "The phone recorded a play meanwhile; fetching its database again"
      Normal; it repeats.  If it fails three times, stop playing on the
      phone and run it again.
  "The phone is not connected (USB debugging on, cable in, allow this
  computer)"
      For --adb: see 09.
  "adb is not installed: ..."
      Run scripts/setup-android-tools.
