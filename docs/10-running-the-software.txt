RUNNING THE SOFTWARE
====================

Source scripts/setup first (01-configuring-the-shell.txt) and create the
database (02-creating-a-database.txt).  The scripts run from any
directory and create the virtual environment on first use.

Scripts
-------

    scripts/play                          desktop player
    scripts/edit-database                 database editor (03)
    scripts/initialize-database --root DIR   create the database (02)
    scripts/change-music-root-directory --root DIR
                                          point the database at a moved
                                          music folder
    scripts/show-music-root-directory     print the music folder the
                                          database records
    scripts/find-stalled-songs            list songs that do not start by
                                          themselves (15)
    scripts/sync-phone                    sync with a phone (11)
    scripts/build-for-android [target]    build the phone app (08)
    scripts/setup-android-tools           install the Android tools (08)
    scripts/run-emulator                  start the Android emulator (08)
    scripts/create-venv                   create or update the virtual
                                          environment
    scripts/test-acoustid                 test the AcoustID lookup

The scripts that use the database take --database FILE (-d FILE) and
otherwise use MILKCRATEVINYL_DATABASE.  Other arguments are passed on to
the program.

Close the player and the editor before a phone sync: they keep the
database in memory and would overwrite the merged result.

Player
------

    scripts/play [--database FILE]

The window has four tabs, one for each task:

    Library     (Ctrl+1)  the library as a table, one row per song, and
                          the search box; duplicates are hidden unless
                          View > Show duplicates is on.
    Playlists   (Ctrl+2)  the playlists, containers and sequences
                          (04 to 06).
    Tags        (Ctrl+3)  a song list of its own, with its search box,
                          on the left and the tag editor on the right
                          (03).  Select the songs to edit in the list.
    Samples     (Ctrl+4)  a song list of its own, and a position bar with
                          two markers, to save part of a song as a file
                          of its own (see "Samples" below).

Each tab has its own "what is playing" line and controls (previous,
play, next, stop, shuffle, position and volume) at the bottom, and
plays on its own.  Music goes on playing when another tab is opened;
the controls of that tab show nothing playing, until something is
played from it.  Pressing Play there pauses what the first tab was
playing, where it was, and starts the music of the tab that is shown.
Going back to the first tab and pressing Play continues its song from
the same place, and pauses the other.  So the Library tab can hold a
song, the Playlists tab a playlist and the Tags tab another song, and
Play on each one switches between them.  Shuffle and the volume are the
same in all the tabs.  The Playback menu and its shortcuts work on the
tab that is shown.

Play in the Library, Tags and Samples tabs starts the selected song; in the
Playlists tab it starts the selected playlist, from its selected entry
or its start.

The Library, Tags and Samples tabs are entirely separate.  Each has its own song
list, with its own search, selection, sort order and columns (View >
Columns changes those of the tab that is shown), and each plays from its
own list.  Only the Tags tab's selection goes to the tag editor; the
Library tab's selection is for rating and for the playlist menu.

The window opens on the tab that was open when it was closed.

If the window stops responding, start the player from a terminal and send
it the signal USR1 from another terminal:

    pkill -USR1 -f desktop/player.py

The player writes on the first terminal where each of its threads is (the
lines of the program each one is in), and keeps running.  Send that text
with the report of the problem, then end the player with Ctrl+C or kill.

Samples
-------

The Samples tab saves a snippet, a part of a song, as a file of its own,
for example to use as a ringtone.  It is a Library tab with a different
position bar.

  1. Select a song and press Play (or double-click it).
  2. The bar shows two arrows.  Drag the left arrow, which points right,
     to where the snippet starts, and the right arrow, which points left,
     to where it ends.  Both arrows start at the ends of the song.  The
     start can be anywhere from 0 to the end arrow; the end is never
     before the start.  A label floats above the left arrow with the
     time of the start, and one below the right arrow with the time of
     the end, and they follow the arrows as they are dragged.  Being on
     opposite sides, they never cover each other, however close the arrows
     are.  While an arrow is held, the length of the snippet also shows in
     the middle of the shaded part.  The length is always shown under the
     bar, with the start and the end.  The arrow that was taken hold of
     last is outlined; while the bar has the keyboard focus (click on it
     or on an arrow; the buttons do not take the focus away), the Left and
     Right arrow keys move that arrow by a tenth of a second, within the
     same limits.  Taking hold of an arrow does not move it, so it can be
     chosen and then set with the keys.
  3. Play plays only the part between the arrows.  At the end arrow the
     music pauses and waits at the start arrow, and Play plays the part
     again.  The position handle stays between the arrows.  Previous goes
     back to the start arrow.  Choosing another song puts both arrows at
     the ends again.
  4. Click "Save Snippet" under the bar (or File > Save Snippet).  The
     message line names the file.

The snippet is saved in the same file type as the song (the audio is
copied, not encoded again, so the sound is the same and no quality is
lost); a song in FLAC gives a snippet in FLAC.  The files are kept in the
folder "Track Samples" in the music folder, named like the song with
"(sample 0m30s-1m05s)" added.  The snippet is added to the database as a
track of its own, with the title "<title> (sample 0:30-1:05)", the album
"Track Samples" and no track number, so it is not taken for a copy of the
song (plays of one are not counted for the other).  Its loudness is
measured, and it is added to the static playlist "Track Samples", which is
made the first time (04).  The next sync copies it to the phone (11).
The song itself is never changed.

Trying out a snippet is not listening: it counts no play and does not
make a song leave a dynamic playlist.  The snippet ends within about a
tenth of a second of the arrow when it plays here; the saved file is cut
at the exact time, to the nearest frame of the file type.

Playing:

  * Double-click a song, or select it and press Enter.  Playback
    continues down the list as sorted and filtered.
  * Right-click songs > Add N tracks to playlist.
  * Select a playlist, container or sequence in the Playlists tab and
    use Play or Shuffle.

Playback menu:

    Play / Pause       Ctrl+Space
    Next               Ctrl+Right
    Previous           Ctrl+Left    (restarts the song after 3 seconds)
    Stop               Ctrl+.
    Next section       Ctrl+Shift+Right
    Random order       Ctrl+R
    Find               Ctrl+F

With Random order on, no song repeats until every song in the list has
played.

Searching.  The search box filters the table.  Every word typed must
match.

    dio              a word starting with "dio" (Dio, Dion; not Audio)
    =dio             the whole word dio
    "the wall"       a phrase
    artist:dio       only in one field: title, artist, album, genre,
                     composer, path

Without a field, the title, artist (also album artist), album, genre,
composer and path are searched, so "classical" finds the genre and also
the song "Classical Gas"; "genre:classical" finds only the genre.  The
editor's file search (03) and the phone (12) use the same language; the
phone has no composer.

Rating.  Rating menu, Rating column, and the stars next to the playing
song's name (07).  A song counts as played after 20 seconds of
listening, which increases its play count and sets its last played
time.

View menu:

  * Show duplicates.
  * Columns...: choose and order the columns.  Column order, widths and
    window size are remembered between runs.
  * Volume leveling: Off, Track (each song to the target loudness) or
    Album (keeps loudness differences within an album); Target
    loudness... sets the target in LUFS.  Leveling uses loudness values
    stored in the database; songs without one are not adjusted.

File menu: Open Database..., Save Tags, Sync with Phone..., Quit.
Tag edits are stored by Save Tags and changes only the database.

Right-click songs > Detect BPM, Measure loudness: for the selected songs,
stored in the database only (03).

Editor
------

    scripts/edit-database [--database FILE]

See 03-editing-the-database.txt.

Moved music folder
------------------

    scripts/change-music-root-directory --root NEW_DIR

The database stores the music folder and the path of each song relative
to it.  If the folder moves, run this with the new location.  It counts
how many database songs exist under NEW_DIR and refuses if there are
none, makes a backup of the database (FILE.bak-before-change-music-root)
and changes the stored folder.  The paths of the songs do not change.

    scripts/show-music-root-directory

Prints the music folder the database records, alone on a line, and does
not change the database.  Exit status 0: printed, and the folder exists;
1: no folder could be read (no database, or none recorded); 2: printed,
but the folder does not exist on this computer, which a note on standard
error says.  Use it to see why songs are not found.

Data and settings
-----------------

  * Database: the file given by --database or MILKCRATEVINYL_DATABASE.
  * Backups and journals: next to the database.
  * Window layout and columns: stored by Qt in the user's configuration
    (~/.config).
  * Nothing is written to the project directory.

Errors
------

  "no such database (create it with scripts/initialize-database)"
      The database file does not exist.
  "Missing file: <path>" in the player
      A song is in the database but not on disk; check the stored
      music folder (change-music-root-directory).
  "no database: --database was not given and MILKCRATEVINYL_DATABASE is
  not set"
      Source scripts/setup or give --database.
